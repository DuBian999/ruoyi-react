# auth

## Purpose

提供若依后台的认证与授权基础能力，覆盖登录、登出、token 生命周期管理、动态路由构建与按钮级权限判断，是系统访问控制的主干链路。

## ADDED Requirements

### Requirement: 用户登录

系统 SHALL 支持用户通过用户名、密码及图形验证码登录；登录成功后持久化 token 并加载用户权限信息。

#### Scenario: 登录成功
- **WHEN** 用户输入正确的用户名、密码和验证码并提交
- **THEN** 系统保存 token，拉取用户信息与权限，跳转到首页

#### Scenario: 登录失败
- **WHEN** 用户输入错误的用户名或密码（或错误验证码）
- **THEN** 系统提示对应错误信息，不保存 token，停留在登录页

### Requirement: 会话持久化与恢复

系统 SHALL 在页面刷新后基于本地持久化的 token 静默恢复会话，避免用户重复登录。

#### Scenario: 刷新恢复会话
- **WHEN** 用户已登录且 token 有效，刷新页面
- **THEN** 系统静默恢复用户信息与动态路由，无需重新登录

#### Scenario: token 失效
- **WHEN** 用户携带的 token 已过期或无效
- **THEN** 系统提示会话过期，清除本地会话并跳转到登录页

### Requirement: 用户登出

系统 SHALL 支持用户主动登出，清除本地会话并返回登录页。

#### Scenario: 主动登出
- **WHEN** 用户点击登出操作
- **THEN** 系统清除 token 与用户信息，跳转到登录页

### Requirement: 动态路由构建

系统 SHALL 根据后端下发的菜单树动态生成前端路由；未授权的路由不可访问。

#### Scenario: 加载动态路由
- **WHEN** 用户登录成功后获取到菜单树
- **THEN** 系统将菜单转换为路由并挂载，用户可访问被授权的页面

#### Scenario: 访问未授权路由
- **WHEN** 用户访问未被授权的路由地址
- **THEN** 系统拒绝访问并重定向到 404 页面

### Requirement: 按钮级权限判断

系统 SHALL 根据当前用户的权限字符串集合控制按钮或操作的可访问性。

#### Scenario: 拥有权限
- **WHEN** 当前用户拥有某权限字符串
- **THEN** 对应的按钮或操作对用户可见、可用

#### Scenario: 无权限
- **WHEN** 当前用户不拥有某权限字符串
- **THEN** 对应的按钮或操作对用户隐藏或禁用

### Requirement: 用户注册

系统 SHALL 支持新用户注册（仅当后端开启注册功能时可用）。

#### Scenario: 注册成功
- **WHEN** 用户填写合法注册信息并提交
- **THEN** 系统创建账号并提示注册成功

### Requirement: 锁屏

系统 SHALL 支持用户锁定屏幕，解锁需重新校验密码。

#### Scenario: 锁屏与解锁
- **WHEN** 用户触发锁屏后，输入正确密码解锁
- **THEN** 系统进入锁定态，密码校验通过后恢复会话
